# Landscape revisit, 2026-09

See `SURVEY.md` for the June 2026 baseline. This note is the revisit
asked for when Vault MCP and password-manager MCP defaults moved.

## What changed

- HashiCorp `vault-mcp-server` v0.2.0: KV plus PKI, stdio and
  streamable-http. `read_secret` returns the secret value to the model.
- Vault Enterprise 2.1 agentic IAM is GA: Agent Registry, OAuth for
  agents. That is the right product when the secret is dynamic and the
  agent has an identity.
- 1Password still has no first-party vault MCP. Community servers exist.
  1password.dev documents MCP for developers.
- Bitwarden has an official MCP with a large tool surface.
- OWASP MCP Top 10 (2026 beta) still ranks token mismanagement first.

## What did not change

nimvault-mcp is still a local, git-native, whole-file, opaque-blob
wrapper. It does not return plaintext payloads. Mutate stays gated.
That is the opposite of official Vault MCP `read_secret`.

Claiming SOTA against Vault MCP remains a category error. Claiming
SOTA in the nimvault niche remains fair for CLI 0.5 and this MCP.

## Verdict

No default change. Do not add a `get` tool that prints a secret into
the model context. Keep scan/status/list as the agent surface.
